# Every file in this project

A guided index of the repository. If you are looking for *how the pieces fit
together* rather than *what each file is*, read [ARCHITECTURE.md](ARCHITECTURE.md)
first.

## Top level

| File | What it is |
| --- | --- |
| `docs/ARCHITECTURE.md` | How the pieces fit together and why they are shaped that way: everything derived from the dictionary, one pipeline fed by two doors, a clock with hooks instead of sleeps, refusing by name and saying who is asking, findings rather than exceptions, and what is deliberately absent. |
| `docs/FILES.md` | This file. |
| `README.md` | The user-facing documentation: quick start, the message choreography, account behaviours, the endpoint table, configuration, trading through a folder, the worked example against mock-edi, the roadmap. |
| `LICENSE` | MIT, verbatim, so GitHub and `licensee` detect it. The standards-body disclaimer lives in the README instead. |
| `pyproject.toml` | Packaging metadata and the **single source of truth for the version**. Declares the `mock-bank` console script and, notably, zero dependencies. |
| `CHANGELOG.md` | Every release, what it added and what it fixed, in Keep a Changelog form. Nothing is written under `[Unreleased]` by hand; that section points at `changelog.d/` and is filled at release time. |
| `changelog.d/` | One file per changelog entry waiting for a release, named `<issue>.<kind>.md` — or `<issue>.<kind>.<step>.md` when an issue ships in more than one pull request — and holding the bullet's text. A directory of small files instead of one shared section, because every pull request used to edit the same lines of `CHANGELOG.md`, a conflicting pull request gets no CI run at all, and a resolution by hand is one keystroke from dropping an entry. `tools/check_changelog.py --assemble` writes them into a release section and deletes them, and the same tool refuses an entry written into `[Unreleased]` by hand - including one a merge put there without a conflict, which is the failure that made this check necessary. Documented as a directory: a row per fragment would put every pull request back to editing one shared file. |
| `CONTRIBUTING.md` | What the project values, how the two-person team works the issue queue (including when to rebase and when to merge `main` in), where to add each kind of thing, what a good pull request carries, and the release process. |
| `MANIFEST.in` | Adds the Dockerfile, examples and tests to the sdist; without it an sdist carries only the package itself. |
| `Dockerfile` | `python:3.12-slim`, `pip install .`, entrypoint bound to `0.0.0.0:8080`. Built and exercised by CI on every push. |
| `.gitignore` | Build output, virtualenvs, `*.db` files left behind by `--db`. |
| `.gitattributes` | `tests/samples/external/** -text`: the vendored samples keep the bytes their authors published. Without it a Windows checkout rewrites every LF to CRLF, which broke the BAI2 sample's SHA-256 on `windows-latest` alone and was silently rewriting the NACHA samples too. |

## `mockbank/` - the package

| File | What it is |
| --- | --- |
| `mockbank/__init__.py` | The package docstring, `__version__` read from `pyproject.toml` in a checkout or from the installed metadata otherwise, and the public names `Config` and `make_server`. |
| `mockbank/__main__.py` | The command line: `build_parser()` (which `tools/check_docs.py` reads to find every flag), `is_loopback()` and `exposure_warning()` (what to say when the control plane is reachable and unguarded), `check_auth()` (a credential nothing could match is refused at startup), and `main()`. |
| `mockbank/accounts.py` | `BEHAVIOURS`: every account behaviour with what the bank does, declared once - the command line's epilog, the README's behaviour table check and `decide()` all read it. Then the account itself: `FIELDS` (every field a caller may set) and a `check()` that refuses an unknown field or behaviour by naming what would have been accepted, over `create`, `update`, `listing` and the `by_iban` lookup the pipeline uses. Then the bank's judgement: `decide()` (the rule precedence is its docstring, and which side of a payment each behaviour is read from), `book()` and `book_due()` (a debit on its settlement date), and the payment queries. An account also has a `format` (`FORMATS`) and a domestic `account_number`, unique where set; `ROUTING` is the bank's own fictional ABA routing number, and `resolve` names the accounts a file names by number - either format - by their IBANs before `decide`, which knows nothing else (#53). On a NACHA account `return-later`'s reason is an `R` code (`R02` by default), and `schedule_rejected_returns` answers what the three behaviours reject with a return the next business day (#54). `MAX_BALANCE` is the largest balance either side of zero a statement can write, 18 digits of minor units: a balance past it is refused where it is set, `still_to_arrive` is the returns due back and credits waiting that a balance must leave room for, and a payment that would overdraw past it is `AM02` (#106). `DUE_DATES` names every date the bank fixes for something still to happen - a settlement, a return and money arriving - and `move_off` moves what is still due on a day that has just become a holiday to the next business day, while `booked_on` says what has already happened on one (#107). |
| `mockbank/bai2.py` | BAI2: the end-of-day statement in the format US treasury systems read. `RECORDS` declares the 01, 02, 03, 16, 49, 98 and 99 records by field position, and both the writer and the reader are derived from it, so nothing joins a line by hand. `write_statement` takes the same *statement data* `messages.write_camt053` takes, because the two are two renderings of one statement rather than two statements - the tails differ and are keyword-only for that reason, so passing one writer's arguments to the other is a `TypeError` rather than a wrong file; `statements` reduces a file back to the opening balance, entries and closing balance a `camt.053` asserts, and `trailers_agree` recomputes every control total and record count from the records it covers. Amounts are integers in minor units and the type code carries the direction, so only a balance is ever negative and a negative movement is refused. Every alphanumeric field is made safe inside `_record` rather than at the call sites - BAI2 has no escape, so a comma in an account name would shift every field after it and a line break would split the record while the trailers still counted it once - money arriving (#91) is `RECEIVED_CREDIT`, `142`, with the payer's name as the text and their structured reference as the customer reference, and any other credit without a return reason is refused rather than written as a return; and `read` walks each record against the declaration, which is what turns either of those into a failing test. Since #114 it reads a real bank's file: an `88` continuation is folded into the record it continues, because it continues that record's field stream rather than carrying fields of its own; a funds type occupies one field, three (`V`), four (`S`) or 2 + 2n (`D`) depending on its value, so a record's width is a function of its contents; and an amount may be signed or bare. The three transaction type codes - `447` for a payment sent, `257` for one returned, `142` for money arriving - are settled against moov-io/bai2's type code table and a bank's own exports (#127), and `PLACEHOLDER_CODES`, now empty, is where one goes back if it loses its source. Since #128 it also knows where a record ends, which is neither the newline nor the `/` alone: a line starts a record when it begins with a declared code and a separator and otherwise continues the one above, and a `/` ends one when a declared code follows it - so a slash inside a customer reference stays inside it, a `16`'s text runs to the terminator with its commas, and a file that omits terminators still reads. Two readings of the format are named as constants rather than left as habits of the code - `CONTROL_TOTALS_ARE_SIGNED` and `COUNTS_INCLUDE_THE_TRAILER` - and #57 settled both against files from outside the project, which also showed that the two numbers a trailer states are counted over different units: a count counts physical records, continuations included, and a total sums the logical record. |
| `mockbank/clock.py` | Bank time: the cutoff, the weekend, the holiday list and the clock a test moves. `settlement_date` is the rule the whole pipeline hangs on; `business_days_after` is what the returns issue counts with; `advance()` moves the offset and calls the `on_advance` hooks the pipeline registers, so releasing what came due is that code and not this. It holds an offset rather than an instant, and knows nothing about payments. |
| `mockbank/credits.py` | Money arriving (#91): `create` validates what the payer sent - the account by id or IBAN, the amount in minor units in the account's currency, a value date no earlier than bank today, the payer, a structured `reference` and the note - and sets it to book on `clock.settlement_date`, the rule a payment's settlement follows, so a weekend or late credit books on the next business day. `wrap` re-cuts the note at 35 or 70 characters wherever the cut falls, the one thing the bank adds; 140 keeps the payer's lines. What the bank could not report is refused before it is stored: a blank or control character in any text, a BIC that is not one, an amount past the 18 digits a statement balance has, a date that is not `YYYY-MM-DD`. The credit's `camt.054` is then written once as a check, so a stored credit can never fail a release. `book_due` books what has come due, but not into an account closed while it waited: that credit's booking date moves on to the next business day, so a reopened account books it on a day with a statement; `booked_on` and `booked_after` are what the statement reads. |
| `mockbank/direct_debit.py` | Direct debits (#131): what the bank decides about a `pain.008`, with the account holder on the creditor side. `decide` returns the same `Decision` a payment file gets, so the `pain.002` and the answer are written by the same code: the file-level rules are `accounts.rejected_outright`, then the creditor account (held, open, in the collection's currency), then a debtor the bank holds, read through `DEBTOR_SIDE_OF_A_COLLECTION` and never booked. `NOT_ABOUT_A_DEBTOR` names every other behaviour with the reason it does not act. `record` writes the `collection` rows; `listing` and `counts` read them. `book_due` credits the creditor account on the settlement date, on the bank clock, and not into an account closed while the collection waited; `booked_on` and `booked_after` are what a statement's position reads. The ceiling (`AM02`) is in `_reason`. `refuse` is the debtor's bank saying no: before settlement the collection is rejected, after it a return is set for the first day the bank can book it; on a NACHA account the reason is an `R` code and a refusal before settlement comes back as a return entry on the day it would have settled; `schedule_rejected_returns` and `rejected_returns_due` send a NACHA account's rejected collections back as return entries that debit nothing; `_schedule_return` sets the same for a held debtor with `return-later`; `book_returns` debits the creditor account, and `returned_on` and `returned_after` are the position's. |
| `mockbank/drop.py` | The second door: `DropBox` watches `--drop-dir` and feeds each settled file to the same pipeline `POST /payments` uses, filing it under `processed/` or `failed/` with the answer beside it, and writes every released message into `--pickup-dir` to a temporary name and renamed. A file is claimed before it is read so a scan and the poller cannot both take it, and one that could not be moved is remembered rather than read again. `write_released` asks the database what is released and not yet written instead of being handed rows, so a release path nobody remembered still gets its files and a restart does not write them all again; `reclaim` renames back anything a killed run left mid-read, and `check_directories` refuses at startup a drop and pickup pair that would feed the bank its own output. |
| `mockbank/db.py` | SQLite: `SCHEMA` and `INDEXES` as declarations, `SCHEMA_VERSION` recorded in the file, a `connect()` that upgrades an older file and refuses a newer one, the `file`, `payment`, `message`, `statement` and `counter` tables, `next_value` (numbers that never repeat), the control plane's one timestamp format, and the fixed four-account seed, its IBANs built with check digits from `schema.mod97`. Balances are integers in minor units; there is no float in it. Version 7 adds an account's `format` and `account_number`, unique where not blank, and a payment's `creditor_clearing_id`, `transaction_code` and `entry_class`, which a NACHA return echoes; the seed's number is the account part of its IBAN. Version 8 adds the `credit` table, money arriving (#91). |
| `mockbank/messages.py` | The writer half: `write_pain002`, `write_camt054`, `write_camt053` and `write_camt052` (sharing one `Ntry` builder, and the last two one `_account_report` body), mappings handed to `schema.serialize` so every element comes out in declared order. The reader half, which since #131 also reads a `pain.008` into a `CollectionFile` of `CollectionBatch`es of `Collection`s (mandate id and date, sequence type and creditor scheme id carried down from the batch where the transaction leaves them out), with `from_tree` choosing by message: `read_pain001`/`from_tree` turn a `pain.001.001.09` or `.001.03` into a `PaymentFile` of `Batch`es of `Payment`s (amounts in minor units, the requested date evened out between versions), each keeping its `schema.Node` so a finding can name its path; `to_json` is the reading `/_mock/validate` returns. `_incoming` writes money arriving (#91) as a received transfer: the payer as `Dbtr`, the note as `RmtInf/Ustrd` and a structured reference as `RmtInf/Strd/CdtrRefInf/Ref`. |
| `mockbank/nacha.py` | NACHA, read into the same model as a `pain.001`: `RECORDS` declares record types 1, 5, 6, 7, 8 and 9 by field position and width, `Record` reads a line by that declaration, and `inspect` builds a `PaymentFile` of subclassed `Batch`es and `Payment`s, so what is downstream of the reader takes either format. The docstring's table says what each model field comes from and the choices where NACHA has no equivalent (`EndToEndId` is the individual identification number, the debtor account is the company identification). Findings name the line, the record and the field with its columns: line length, routing check digit (`RC01`), entry hash and block count (`FF01`), counts (`AM18`) and credit totals (`AM10`), and any entry that is not a credit; and, as for a `pain.001`, `DT01` for a past effective date and `AM05` for a repeated identification number. A numeric field can be declared optional (`OPTIONAL_N`), as the file creation time is. The receiving DFI's routing number is kept as `creditor_clearing_id`, the field the `pain.001` reader fills from `ClrSysMmbId`. `acknowledgement` writes what a NACHA account is sent in place of a `pain.002` (#53): plain text, one fact to a line, the mock's own shape because NACHA specifies none. A return entry (codes 21, 31, 41, 51, with its addenda 99, declared as `RETURN_ADDENDA`) is read as a `Return`, not a payment, and `return_file` writes one from the declaration - one return per payment, with counts, hash, totals and padding computed - so it reads back with no finding (#54). Every entry counts in its control total by its code's second digit (`side`): 1 to 4 a credit and 6 to 9 a debit, returns included, and both totals are checked (#55). A debit entry (`27`, `37`, `47`) is read into `Collection`, `CollectionBatch` and `CollectionFile`, the `pain.008` model filled from records (#176); a file is of payments or of collections, and `NOT_READ` names what is neither. |
| `mockbank/outbox.py` | What the bank sends and when: `queue_status` puts the status on the `message` table - the `pain.002`, or for an account whose `format` is `nacha` the plain acknowledgement - due `--status-delay-ms` after receipt - a file refused before it had a `MsgId` too, numbered `MB-P002-N…` from its own sequence with no account when none could be read, unless its debtor is `silent` - `release_due` books what has come due, writes one `camt.054` per account per booking and releases what is due (the clock's hook), `upcoming` says what a file will still bring, and `issue_statements` writes a `camt.053` per open account for each business day the clock passed the end of; `issue_report` writes a `camt.052` for one account on request, from the same `_position` a statement states (#132). The mailbox reads the same table: `collect` (peeking, and filtering on a literal type prefix rather than a `LIKE` pattern), `message`, `unread`, and `raw`, which hands back a sequence of documents rather than one invented root. `_release_credits` books money arriving on its day and sends its `camt.054`, and the statement counts it and shows it as a received transfer (#91). `queued` is the read-only listing of what has not been released (#155): the messages written and held back, and the ones the bank will write when a payment settles, money arrives or a return comes due. |
| `mockbank/schema.py` | The ISO 20022 dictionary: `pain.001.001.09` and `.001.03`, `pain.008.001.08` (#131), `pain.002.001.10`, `camt.054.001.08`, `camt.053.001.08` and `camt.052.001.08` declared as element trees, with the shared shapes (address, account, agent, party) declared once; the code sets; `walk`/`check` (structural findings), `read` (tree to mapping) and `build`/`serialize` (mapping to tree in declared order); the ISO 13616 IBAN check (`iban_is_valid`, `mod97`) that the seed, the accounts endpoint and the validator share; the choices the standard leaves open, in `CHOICES`. |
| `mockbank/handler.py` | The request handler, and nothing about any endpoint: it splits the path and query, runs `_authorised` before the body is read and before routing (so `--auth` covers every endpoint and a `404` cannot be used to map what exists), reads the body (refusing chunked, oversized and short ones by name), takes the lock, and looks the request up in the route table. A path the table does not have is a `404` naming `SUPPORTED`; one it has only with other methods is a `405` naming them. Every answer leaves through `raw`, so every request is logged before its answer goes out, and every `PRUNE_EVERY` requests the log is pruned. |
| `mockbank/routes/__init__.py` | The route table: `route(method, pattern, note=)` registers a function, and `SUPPORTED` and `NOTES`, what the index, the `404` body and `/_mock/state` list, are computed from it in registration order (`/index.html` is registered but not listed), `find` looks a request up and says which methods a path has when the one asked for is not among them. Patterns are written the way the index lists them, `<name>` for a segment that can be anything. Also the helpers a route reads the request with: `first`, `flag` (so `?leave=0` means what it says) and `json_body`. |
| `mockbank/routes/accounts.py` | `GET`/`POST /_mock/accounts`, `GET`/`PATCH /_mock/accounts/<id>` `GET /_mock/accounts/<id>/statements` and `POST /_mock/accounts/<id>/report`, which books what is due first and delivers the `camt.052` at once; an unknown account is a `404` listing the ones the bank holds. |
| `mockbank/routes/clock.py` | `POST /_mock/advance` (`?days=N` or `?to=YYYY-MM-DD`, exactly one) and `GET`/`PUT /_mock/holidays`, a whole list replaced whole. `PUT /_mock/holidays` moves what is still due on a newly declared holiday to the next business day, and refuses today once something has booked on it (#107). |
| `mockbank/routes/credits.py` | `POST /_mock/credits`, a credit arriving, answered `201` with when it books or refused with why; and `GET /_mock/credits`, newest first. |
| `mockbank/routes/collections.py` | `GET /_mock/collections`, every collection the bank decided on, newest first, and `GET /_mock/collections/<EndToEndId>`, the newest with that id or with `?all` every one. A miss is a `404` naming the ids it has. `POST /_mock/collections/<EndToEndId>/refuse` is the debtor's bank saying no: it queues the further `pain.002` for a refusal before settlement, and releases at once so a return due today is already in the mailbox. |
| `mockbank/routes/control.py` | Health, state, reset, the behaviours, `/_mock/dictionary`, and the index page, built from the route table; `PLANNED`, the endpoints promised but not built, empty in this release. |
| `mockbank/routes/mailbox.py` | The mailbox (collecting, `?leave`, `?raw`, `?type`), one message, `unread`, and `GET /_mock/requests`, whose `?path=` is a literal prefix rather than a `LIKE` pattern. Every mailbox read releases first, so peeking and collecting see the same bank. `GET /_mock/queue` is the one path that does not release first. |
| `mockbank/routes/payments.py` | `POST /payments`, the HTTP door onto `State.receive` and nothing more, and `GET /_mock/payments` and `/_mock/payments/<EndToEndId>`. |
| `mockbank/routes/transport.py` | `GET /_mock/drop`, what the folder transport is doing, and `POST /_mock/drop/scan`, a `409` on a mock with no drop directory. |
| `mockbank/routes/validate.py` | `POST /_mock/validate`: the findings as prose, or as JSON when the request accepts it; nothing is stored. The prose summary counts a `pain.008`'s collections where a `pain.001`'s payments are counted. |
| `mockbank/server.py` | `Config`, everything the server can be told, and `make_server`, which opens the database into a `State` before binding - so a `--db` this version cannot read is refused before the port is taken - and binds a `Handler` to it. `server_bind` skips the reverse DNS lookup `http.server` would do on the bind address. `SUPPORTED` is re-exported from here for the tests. |
| `mockbank/state.py` | `State`, what survives between requests: the connection, the clock and the lock over them, retention (`prune`, which keeps a message the pickup directory has not received), `reset`, `snapshot`, and `receive` - the pipeline both doors feed, read, validate, decide, book, queue, release. |
| `mockbank/validate.py` | `inspect`/`validate`: file-level refusals (empty, signed or encrypted, DTD, not XML, a message the mock does not read), the walker's structural findings, and the semantic checks (`AM18`, `AM10`, `AC01`, `AM03`, `AM05`, `DT01`), for a `pain.008` turned round to the creditor's side by `_collection_meaning` (#131); `refusal` is the finding that refuses a whole file, with the table of codes in the docstring; `render` makes a finding one line of prose. Never raises. |

## `tests/` - end-to-end, over HTTP

| File | What it is |
| --- | --- |
| `tests/support.py` | `MockServerCase`: starts a real server on an ephemeral port per test class and offers `get`/`post`/`patch`/`put`/`request` helpers returning a `Response` with `.json()`. `FileDatabaseCase` is the same on a `--db` file that a test can restart, for the questions `:memory:` cannot answer. Arms a faulthandler watchdog when `MOCKBANK_TEST_WATCHDOG` is set. |
| `tests/test_auth.py` | `--auth`: no credentials is a `401` with `WWW-Authenticate` and the right ones a `200`, a wrong or partly-right one is a `401`, every endpoint including `/_mock/health` is behind it, a malformed `Authorization` header is a `401` rather than a `500`, and an unauthenticated payment file is never read. The exposure warning is checked on the function and again on a real subprocess, where `-q` must not silence it. |
| `tests/test_bai2_statements.py` | The wiring, over HTTP against a real mock: an account whose `format` is `nacha` is sent BAI2 and not `camt.053`, the other accounts in the same payment file still get `camt.053`, the trailers agree, the statement row records the BAI2 message, and the file carries the statement number. That the counter is shared between formats, so a format change does not restart the numbering and collide with statements already sent. `statement-gap` leaving one detail out with the balances unchanged, short by exactly the missing entry, and the file still internally consistent. And that the mailbox serves it as text and the pickup directory writes it as `.bai2`, from a mock started with `--pickup-dir`. |
| `tests/test_balance_limit.py` | A balance a statement cannot write is refused where it would arise (#106): past 18 digits at `PATCH` and at creation, either side of zero; the largest there is still makes a statement; a `PATCH` counts a return still to come and a credit waiting to book; a credit counts a return still to come; and a debit that would overdraw past it is `AM02`, alone, after another in the same file, or after one accepted for a later day. |
| `tests/test_holiday_after_acceptance.py` | A holiday declared after something was due on it (#107): a payment, a return and a credit due on a Friday that becomes a holiday move to Monday, and both accounts' statements still chain to their balances; today is refused once something has booked on it, and declared when nothing has; a day already past moves nothing. |
| `tests/test_bai2.py` | BAI2 against the `camt.053` of the same statement: both writers are handed the same data, and the two files have to agree about the opening balance, the entries in order with their references and amounts, and the closing balance - including when the account is overdrawn, when there are no entries, and under `statement-gap`, where neither writer is allowed to notice that the balances do not reconcile. Then the trailers, recomputed from the records they cover, with a wrong total or count in each of the three refused by name; the two type-code choices; and the fields that would end a record early, since BAI2 has no escape and a creditor called `Umbrella, Logistics, S.A.` would otherwise shift every field after it. |
| `tests/test_changelog_tools.py` | `tools/check_changelog.py` as the command line CI runs, against a throwaway repository with its own `CHANGELOG.md`, `changelog.d/` and git history: a fragment with an unknown kind, no issue number or an empty body is refused by name; a `mockbank/` change with no fragment fails and the `no changelog` label lifts it; a fragment deleted without a release is noticed; `--assemble` groups by kind, sorts #9 before #10, indents the body as a bullet, fixes both link references, empties the directory, refuses rather than writing a section twice, and produces a changelog the check accepts. The last test is a git question rather than a tool one: two branches each adding an entry merge in either order with no conflict, which is why the directory exists. |
| `tests/test_clock.py` | Bank time: a payment at 16:00 on a Friday settles on Monday and on Tuesday when Monday is a holiday, 15:00 exactly is already too late, three business days after a Thursday is the next Tuesday, `?days=3` from a Thursday lands on Sunday and says it counted calendar days, the clock never goes backwards, and a reset returns to where `--clock` put it rather than to real time. Every date asserts the weekday it falls on. |
| `tests/test_unwritable_inputs.py` | Input the bank takes and then cannot write an answer for (#166), a test per case, each one also asserting the symptom that made these expensive is absent: that `POST /_mock/advance` and the mailbox still answer afterwards, walked over several days because a return scheduled days out only fails when the clock reaches it. An empty account name is refused and a long one is written shortened, so the door is not quietly tightened into refusing every name a message has to cut. A `MsgId` over 35 characters and an 18-digit control sum are `422` with nothing booked and nothing queued - neither file can be built by `schema.serialize` at all, so both are serialized valid and then edited, which is what a client's file is anyway. A NACHA account's `InstrId` is held to the return addenda's own declared width, and the same value is accepted on an ISO 20022 account, where nothing carries a trace number. A format switch is refused while a return is scheduled and allowed once it has gone back, because the refusal is "not yet" and not "never". A creditor account given as `Othr/Id` is accepted and reported as `Othr/Id`, with a strict IBAN still going in the `IBAN` element, and one test pins the reason the choice uses the XSD's pattern rather than `schema.iban_is_valid`, which forgives spaces on purpose. |
| `tests/test_bank_clock_stamps.py` | Which control-plane timestamps are bank time and which are real time (#147). A payment's `booked_at` moves with the clock that booked it - two payments booked either side of an advance are days apart, which is the one assertion here that cannot go vacuous as the real date moves; a credit's two stamps agree about which clock they are on; `returned_at` is the bank's day the return went out, for a `return-later` return and a NACHA rejection, and that day is the due day only when the clock was advanced to it. A file's `received_at` read back over HTTP, beside the `msg_id` on each of its payments. And the other side of the rule, so it is a rule and not a direction: the request log and `started` stay on the real clock. |
| `tests/test_credits.py` | Money arriving (#91): a credit books on its value date and not before, and the statements around it reconcile by hand-worked balances; a weekend one books on Monday with its own `ValDt`; booking sends a `camt.054` received transfer; the statement's entry is `CRDT` under `PMNT`/`RCDT`/`ESCT` with the payer, the note lines and the structured reference apart from them; `wrap` 35 splits an invoice number across lines; a credit with no reference has neither; every message walks clean; and what the bank would not book is refused with why, each case the #96 review found included, after which the bank still answers. | `examples/payment_run.py` | A payment run against mock-sap, #16's contract in two halves. Paying: selects the open supplier items that are due (`K`, not cleared, not blocked), joins each to its supplier invoice through the accounting document for the supplier's invoice number and the account the invoice names, pays them in one `pain.001` with that number as `EndToEndId`, and matches the `pain.002` back by `MsgId` and `EndToEndId`. Reconciling: each `camt.053` for the paying account is checked (opening plus entries is closing) and posted to SAP as a `FINSTA01`, a debit's direction written as SAP writes a negative, with the minus after it. SAP clears what it paid; a statement that does not add up names the accepted payment for exactly the missing amount as unreconciled (every candidate, when several have that amount), and its item stays open. With `file_format="nacha"` it pays by ACH (#55): a NACHA file it writes itself from the run, the acknowledgement read back, and suppliers paid to SAP's routing and account numbers. The run's identification goes into the header's creation time and file ID modifier exactly, which holds one to three letters or digits: two runs on one day are never one file, and a longer identification is refused before anything is selected. An item an entry cannot carry is skipped with the reason: the reference, the amount, the account number or the name. Reconciling in NACHA mode reads a BAI2 statement as well as a `camt.053`, by hand, into the same plain statement (`bai2_statements`, `camt_statements`). `bai2_records` finds the records by #128's rule - a line starts one only with a record code and a comma, a mid-line `/` ends one only when a code and a comma follow, anything else continues the record above - and an `88` continues one; `funds_width` says how far a funds type moves the references (#130); amounts are cents, and a movement's direction is its type code's range. An account without both ledger balances is read as no statement rather than stopping the file. A returned item's `R` code comes from the bank's NACHA return file (`nacha_return_reasons`), kept on the run (#57). |

## `tools/` - what CI checks

| File | What it is |
| --- | --- |
| `tools/check_docs.py` | Fails if a tracked file has no row here, if a row names a missing file, if the README's layout block misses a module, if a CLI flag is unmentioned in the README, if a behaviour has no row in the README's table, if `docs/ARCHITECTURE.md` names a file that does not exist, or if the README's endpoint table and the route table disagree, in either direction. |
| `tools/check_xsd.py` | Holds the dictionary and the mock's output to the published XSDs, fetched from pinned commits and checked by SHA-256 into `tools/.xsd/`: compares every declared element with the XSD (place, order, occurrence, group or value, length), and with `xmllint` validates the project's clean samples, the external ones (and fails the invalid ones), and every message a running mock writes, intraday reports included. A fetch that fails on the network is tried three times with a growing pause; one with the wrong hash stops at once. Skips without a network or `xmllint`; `--require`, which CI passes, makes a skip a failure. |
| `tools/release.py` | Cuts a release in one step, run by the maintainer on a clean `main` after the release pull request has merged: it refuses, then tags, pushes and publishes the GitHub Release, which is what uploads to PyPI. Every refusal is something that has gone wrong in a real release - a dirty tree, a branch that is not `main` or a detached HEAD, a `main` that disagrees with `origin/main`, a `pyproject.toml` that does not say the version, no dated changelog section for it, fragments still waiting in `changelog.d/`, or the CI workflow not green on the commit about to be tagged - green decided by `ci_verdict`, a pure function over GitHub's answer, from the CI workflow's own runs only, since the scheduled release check attaches to the same commit and is correctly failing until the tag exists. The tag is asked of **origin** rather than of this clone, because after a failed push the two disagree and that is how a release gets tagged at the wrong commit; `gh release create --verify-tag` is the other half of that guard. The Release body is the version's own `CHANGELOG.md` section, extracted by `notes_for` and passed with `--notes-file`: on a squash-merged repository `--generate-notes` restates the commit titles, which the changelog says better and which somebody reviewed. Publishing is last because it is the only irreversible step. `--dry-run` prints each step and does none. On a version already tagged and published it says so and stops, which it asks before examining the tree, so an entry waiting for the next release is not read as a problem with an old one. Standard library, `git` and `gh`. |
| `tools/check_release.py` | Asks afterwards whether a release finished: the version `main` claims has a tag, and that tag has a published GitHub Release. Passes when there is no dated section for the version yet, which is the ordinary state between releases and the case that must not cry wolf. Fails naming what is missing when `main` carries a dated release with no tag, or a tag with no Release, or a draft one - a draft does not trigger the publish workflow, so PyPI keeps serving the previous version. Whether `gh` can resolve the repository at all is asked separately from whether the Release exists, so a checkout with no GitHub remote skips rather than reporting a false alarm; `--require`, which the workflow passes, makes that skip a failure. |
| `tools/check_examples.py` | Holds this repository's copies of other projects' examples to their originals. `examples/invoice_check.py` is mock-sap's, copied byte-for-byte because example code is not importable across repositories - no wheel carries `examples` - and the alternative is forking logic that is tested there. Compares against the **tip** of the source repository's default branch, not a pinned commit, which is the opposite of `check_xsd.py`: a run that passes today and fails tomorrow with nothing changed here is the point, because the drift comes from elsewhere. `--update` takes theirs, and the failure carries a unified diff. `--require` turns a fetch it could not make into a failure, as `check_xsd.py` and `check_release.py` do, so being offline skips rather than blocks while CI stays strict; a 404 is refused at once rather than retried, because the original moving needs a new path and not another attempt. |
| `tools/check_changelog.py` | Fails if the changelog is malformed, if a released section changed, if `[Unreleased]` holds anything but the pointer at `changelog.d/`, if a fragment is named wrongly or empty, if a fragment vanished without a release being cut, or if a pull request touches `mockbank/` without adding a fragment (lifted by the `no changelog` label). `--assemble VERSION --date` writes the fragments into a release section, fixes the link references and deletes them, and does nothing the second time. |

## `.github/workflows/`

| File | What it is |
| --- | --- |
| `.github/workflows/ci.yml` | Tests on nine Python and OS combinations; the docs and changelog checks and the XSD check; the curl tour and the example client as a smoke test, each against a plain mock and again against one started with `--auth`; the tour once more against a mock trading through a folder; the `pay_invoices` example against mock-edi installed from PyPI; a wheel build that sends a real payment file through the installed console script; and the container image, which is also where `--auth` is checked through a published port. |
| `.github/workflows/release-check.yml` | `check_release.py --require`, daily at 07:00 UTC and on demand. Not on push: on the release commit the tag cannot exist yet, so a push trigger would fail every release by design and be switched off within a month. `fetch-depth: 0` so that a missing tag means a missing tag rather than a shallow clone. |
| `.github/workflows/check-examples.yml` | `check_examples.py --require`, on push and pull request *and* daily at 07:10 UTC. Per-push because a pull request that edits a copy should fail on that pull request; daily as well because the drift comes from another repository, which can move for weeks with no commit here to trigger anything. Its own workflow rather than a step in `ci.yml`, so the daily run is one small job instead of the nine-way test matrix, and ten minutes after `release-check.yml` so two unrelated watchdogs do not report together and read as one problem. |
| `.github/workflows/publish.yml` | Trusted Publishing to PyPI on a GitHub Release, or to TestPyPI on a manual run, after checking the tag, `pyproject.toml` and the built wheel agree. |
