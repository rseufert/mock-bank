# Every file in this project

A guided index of the repository. If you are looking for *how the pieces fit
together* rather than *what each file is*, read [ARCHITECTURE.md](ARCHITECTURE.md)
first.

## Top level

| File | What it is |
| --- | --- |
| `docs/ARCHITECTURE.md` | How the pieces fit together and why they are shaped that way: everything derived from the dictionary, one pipeline fed by two doors, a clock with hooks instead of sleeps, refusing by name and saying who is asking, findings rather than exceptions, and what is deliberately absent. |
| `docs/FILES.md` | This file. |
| `README.md` | The user-facing documentation: quick start, the message choreography, account behaviours, the endpoint table, configuration, trading through a folder, the worked example against mock-edi, the roadmap. |
| `LICENSE` | MIT, verbatim, so GitHub and `licensee` detect it. The standards-body disclaimer lives in the README instead. |
| `pyproject.toml` | Packaging metadata and the **single source of truth for the version**. Declares the `mock-bank` console script and, notably, zero dependencies. |
| `CHANGELOG.md` | Every release, what it added and what it fixed, in Keep a Changelog form. Nothing is written under `[Unreleased]` by hand; that section points at `changelog.d/` and is filled at release time. |
| `changelog.d/` | One file per changelog entry waiting for a release, named `<issue>.<kind>.md` and holding the bullet's text. A directory of small files instead of one shared section, because every pull request used to edit the same lines of `CHANGELOG.md`, a conflicting pull request gets no CI run at all, and a resolution by hand is one keystroke from dropping an entry. `tools/check_changelog.py --assemble` writes them into a release section and deletes them, and the same tool refuses an entry written into `[Unreleased]` by hand - including one a merge put there without a conflict, which is the failure that made this check necessary. Documented as a directory: a row per fragment would put every pull request back to editing one shared file. |
| `CONTRIBUTING.md` | What the project values, how the two-person team works the issue queue (including when to rebase and when to merge `main` in), where to add each kind of thing, what a good pull request carries, and the release process. |
| `MANIFEST.in` | Adds the Dockerfile, examples and tests to the sdist; without it an sdist carries only the package itself. |
| `Dockerfile` | `python:3.12-slim`, `pip install .`, entrypoint bound to `0.0.0.0:8080`. Built and exercised by CI on every push. |
| `.gitignore` | Build output, virtualenvs, `*.db` files left behind by `--db`. |

## `mockbank/` - the package

| File | What it is |
| --- | --- |
| `mockbank/__init__.py` | The package docstring, `__version__` read from `pyproject.toml` in a checkout or from the installed metadata otherwise, and the public names `Config` and `make_server`. |
| `mockbank/__main__.py` | The command line: `build_parser()` (which `tools/check_docs.py` reads to find every flag), `is_loopback()` and `exposure_warning()` (what to say when the control plane is reachable and unguarded), `check_auth()` (a credential nothing could match is refused at startup), and `main()`. |
| `mockbank/accounts.py` | `BEHAVIOURS`: every account behaviour with what the bank does, declared once - the command line's epilog, the README's behaviour table check and `decide()` all read it. Then the account itself: `FIELDS` (every field a caller may set) and a `check()` that refuses an unknown field or behaviour by naming what would have been accepted, over `create`, `update`, `listing` and the `by_iban` lookup the pipeline uses. Then the bank's judgement: `decide()` (the rule precedence is its docstring, and which side of a payment each behaviour is read from), `book()` and `book_due()` (a debit on its settlement date), and the payment queries. An account also has a `format` (`FORMATS`) and a domestic `account_number`, unique where set; `ROUTING` is the bank's own fictional ABA routing number, and `resolve` names the accounts a file names by number - either format - by their IBANs before `decide`, which knows nothing else (#53). On a NACHA account `return-later`'s reason is an `R` code (`R02` by default), and `schedule_rejected_returns` answers what the three behaviours reject with a return the next business day (#54). |
| `mockbank/clock.py` | Bank time: the cutoff, the weekend, the holiday list and the clock a test moves. `settlement_date` is the rule the whole pipeline hangs on; `business_days_after` is what the returns issue counts with; `advance()` moves the offset and calls the `on_advance` hooks the pipeline registers, so releasing what came due is that code and not this. It holds an offset rather than an instant, and knows nothing about payments. |
| `mockbank/drop.py` | The second door: `DropBox` watches `--drop-dir` and feeds each settled file to the same pipeline `POST /payments` uses, filing it under `processed/` or `failed/` with the answer beside it, and writes every released message into `--pickup-dir` to a temporary name and renamed. A file is claimed before it is read so a scan and the poller cannot both take it, and one that could not be moved is remembered rather than read again. `write_released` asks the database what is released and not yet written instead of being handed rows, so a release path nobody remembered still gets its files and a restart does not write them all again; `reclaim` renames back anything a killed run left mid-read, and `check_directories` refuses at startup a drop and pickup pair that would feed the bank its own output. |
| `mockbank/db.py` | SQLite: `SCHEMA` and `INDEXES` as declarations, `SCHEMA_VERSION` recorded in the file, a `connect()` that upgrades an older file and refuses a newer one, the `file`, `payment`, `message`, `statement` and `counter` tables, `next_value` (numbers that never repeat), the control plane's one timestamp format, and the fixed four-account seed, its IBANs built with check digits from `schema.mod97`. Balances are integers in minor units; there is no float in it. Version 7 adds an account's `format` and `account_number`, unique where not blank, and a payment's `creditor_clearing_id`, `transaction_code` and `entry_class`, which a NACHA return echoes; the seed's number is the account part of its IBAN. |
| `mockbank/messages.py` | The writer half: `write_pain002`, `write_camt054` and `write_camt053` (sharing one `Ntry` builder), mappings handed to `schema.serialize` so every element comes out in declared order. The reader half: `read_pain001`/`from_tree` turn a `pain.001.001.09` or `.001.03` into a `PaymentFile` of `Batch`es of `Payment`s (amounts in minor units, the requested date evened out between versions), each keeping its `schema.Node` so a finding can name its path; `to_json` is the reading `/_mock/validate` returns. |
| `mockbank/nacha.py` | NACHA, read into the same model as a `pain.001`: `RECORDS` declares record types 1, 5, 6, 7, 8 and 9 by field position and width, `Record` reads a line by that declaration, and `inspect` builds a `PaymentFile` of subclassed `Batch`es and `Payment`s, so what is downstream of the reader takes either format. The docstring's table says what each model field comes from and the choices where NACHA has no equivalent (`EndToEndId` is the individual identification number, the debtor account is the company identification). Findings name the line, the record and the field with its columns: line length, routing check digit (`RC01`), entry hash and block count (`FF01`), counts (`AM18`) and credit totals (`AM10`), and any entry that is not a credit; and, as for a `pain.001`, `DT01` for a past effective date and `AM05` for a repeated identification number. A numeric field can be declared optional (`OPTIONAL_N`), as the file creation time is. The receiving DFI's routing number is kept as `creditor_clearing_id`, the field the `pain.001` reader fills from `ClrSysMmbId`. `acknowledgement` writes what a NACHA account is sent in place of a `pain.002` (#53): plain text, one fact to a line, the mock's own shape because NACHA specifies none. A return entry (codes 21, 31, 41, 51, with its addenda 99, declared as `RETURN_ADDENDA`) is read as a `Return`, not a payment, and `return_file` writes one from the declaration - one return per payment, with counts, hash, totals and padding computed - so it reads back with no finding (#54). |
| `mockbank/outbox.py` | What the bank sends and when: `queue_status` puts the status on the `message` table - the `pain.002`, or for an account whose `format` is `nacha` the plain acknowledgement - due `--status-delay-ms` after receipt - a file refused before it had a `MsgId` too, numbered `MB-P002-N…` from its own sequence with no account when none could be read, unless its debtor is `silent` - `release_due` books what has come due, writes one `camt.054` per account per booking and releases what is due (the clock's hook), `upcoming` says what a file will still bring, and `issue_statements` writes a `camt.053` per open account for each business day the clock passed the end of. The mailbox reads the same table: `collect` (peeking, and filtering on a literal type prefix rather than a `LIKE` pattern), `message`, `unread`, and `raw`, which hands back a sequence of documents rather than one invented root. |
| `mockbank/schema.py` | The ISO 20022 dictionary: `pain.001.001.09` and `.001.03`, `pain.002.001.10`, `camt.054.001.08` and `camt.053.001.08` declared as element trees, with the shared shapes (address, account, agent, party) declared once; the code sets; `walk`/`check` (structural findings), `read` (tree to mapping) and `build`/`serialize` (mapping to tree in declared order); the ISO 13616 IBAN check (`iban_is_valid`, `mod97`) that the seed, the accounts endpoint and the validator share; the choices the standard leaves open, in `CHOICES`. |
| `mockbank/handler.py` | The request handler, and nothing about any endpoint: it splits the path and query, runs `_authorised` before the body is read and before routing (so `--auth` covers every endpoint and a `404` cannot be used to map what exists), reads the body (refusing chunked, oversized and short ones by name), takes the lock, and looks the request up in the route table. A path the table does not have is a `404` naming `SUPPORTED`; one it has only with other methods is a `405` naming them. Every answer leaves through `raw`, so every request is logged before its answer goes out, and every `PRUNE_EVERY` requests the log is pruned. |
| `mockbank/routes/__init__.py` | The route table: `route(method, pattern, note=)` registers a function, and `SUPPORTED` and `NOTES`, what the index, the `404` body and `/_mock/state` list, are computed from it in registration order (`/index.html` is registered but not listed), `find` looks a request up and says which methods a path has when the one asked for is not among them. Patterns are written the way the index lists them, `<name>` for a segment that can be anything. Also the helpers a route reads the request with: `first`, `flag` (so `?leave=0` means what it says) and `json_body`. |
| `mockbank/routes/accounts.py` | `GET`/`POST /_mock/accounts`, `GET`/`PATCH /_mock/accounts/<id>` and `GET /_mock/accounts/<id>/statements`; an unknown account is a `404` listing the ones the bank holds. |
| `mockbank/routes/clock.py` | `POST /_mock/advance` (`?days=N` or `?to=YYYY-MM-DD`, exactly one) and `GET`/`PUT /_mock/holidays`, a whole list replaced whole. |
| `mockbank/routes/control.py` | Health, state, reset, the behaviours, `/_mock/dictionary`, and the index page, built from the route table; `PLANNED`, the endpoints promised but not built, empty in this release. |
| `mockbank/routes/mailbox.py` | The mailbox (collecting, `?leave`, `?raw`, `?type`), one message, `unread`, and `GET /_mock/requests`, whose `?path=` is a literal prefix rather than a `LIKE` pattern. Every mailbox read releases first, so peeking and collecting see the same bank. |
| `mockbank/routes/payments.py` | `POST /payments`, the HTTP door onto `State.receive` and nothing more, and `GET /_mock/payments` and `/_mock/payments/<EndToEndId>`. |
| `mockbank/routes/transport.py` | `GET /_mock/drop`, what the folder transport is doing, and `POST /_mock/drop/scan`, a `409` on a mock with no drop directory. |
| `mockbank/routes/validate.py` | `POST /_mock/validate`: the findings as prose, or as JSON when the request accepts it; nothing is stored. |
| `mockbank/server.py` | `Config`, everything the server can be told, and `make_server`, which opens the database into a `State` before binding - so a `--db` this version cannot read is refused before the port is taken - and binds a `Handler` to it. `server_bind` skips the reverse DNS lookup `http.server` would do on the bind address. `SUPPORTED` is re-exported from here for the tests. |
| `mockbank/state.py` | `State`, what survives between requests: the connection, the clock and the lock over them, retention (`prune`, which keeps a message the pickup directory has not received), `reset`, `snapshot`, and `receive` - the pipeline both doors feed, read, validate, decide, book, queue, release. |
| `mockbank/validate.py` | `inspect`/`validate`: file-level refusals (empty, signed or encrypted, DTD, not XML, a message the mock does not read), the walker's structural findings, and the semantic checks (`AM18`, `AM10`, `AC01`, `AM03`, `AM05`, `DT01`), with the table of codes in the docstring; `render` makes a finding one line of prose. Never raises. |

| `examples/statement.py` | Reads `camt.053` documents on stdin and does the arithmetic the tour is about: closing balance equals opening balance plus the entries, to the cent. Says so when they do not add up, which is what `statement-gap` produces. |
| `examples/pay_invoices.py` | The worked integration with mock-edi: collects the supplier's EDIFACT `INVOIC`s, pays each on its due date in one `pain.001` whose `MsgId` is derived from its payments, and reconciles the `pain.002`, `camt.054` and `camt.053` by `EndToEndId` and `MsgId`. | `examples/bank_messages.py` | What `pay_invoices.py` and `payment_run.py` share: the one HTTP call, which answers `NO_ANSWER` rather than raising when a host does not answer, and reading what mock-bank sends back (`bank_documents` splits `?raw`, `entries` reads a `camt.053` or `camt.054`). Copying either example means copying this file and nothing else. |
| `examples/payment_run.py` | A payment run against mock-sap, #16's contract in two halves. Paying: selects the open supplier items that are due (`K`, not cleared, not blocked), joins each to its supplier invoice through the accounting document for the supplier's invoice number and the account the invoice names, pays them in one `pain.001` with that number as `EndToEndId`, and matches the `pain.002` back by `MsgId` and `EndToEndId`. The `MsgId` is the run date and identification, as `F110`'s are, so the same run sent twice is `DUPL` and the refusal of the copy leaves the first file's outcome alone. Reconciling: each `camt.053` for the paying account is checked (opening plus entries is closing) and posted to SAP as a `FINSTA01`, a debit's direction written as SAP writes a negative, with the minus after it. SAP clears what it paid; a statement that does not add up names the accepted payment for exactly the missing amount as unreconciled (every candidate, when several have that amount), and its item stays open. A return is a credit on a later statement under the original `EndToEndId`: SAP reverses the clearing and the item is `returned`, with the bank's reason, and owed again. Stdlib only; imports neither mock. |

Reconciling: a clean run is cleared in SAP (test 1); under `statement-gap` the missing payment is unreconciled and its item stays open (test 5); a Friday run after the cutoff waits for Monday's statement, and Friday's empty one posts harmlessly (test 6); posting a statement twice clears nothing twice. Returning (test 3): a payment `return-later` sends back reopens its invoice in SAP, open again like one never paid but with `ClearingIsReversed` set, and the next run selects it. And when something answers badly: SAP refusing a statement is recorded against it, a bank that answers 404 is three named problems, a bank or SAP on a port nothing listens on is named as not answering, and a shortfall two payments could explain names both. Each test posts its own `INVOIC`s dated with the bank's date, to mock-sap's seeded suppliers, which bank at mock-bank's accounts; a blocked invoice is blocked on the supplier invoice and is never paid. ## `tools/` - what CI checks

| File | What it is |
| --- | --- |
| `tools/check_docs.py` | Fails if a tracked file has no row here, if a row names a missing file, if the README's layout block misses a module, if a CLI flag is unmentioned in the README, if a behaviour has no row in the README's table, if `docs/ARCHITECTURE.md` names a file that does not exist, or if the README's endpoint table and the route table disagree, in either direction. |
| `tools/check_xsd.py` | Holds the dictionary and the mock's output to the published XSDs, fetched from pinned commits and checked by SHA-256 into `tools/.xsd/`: compares every declared element with the XSD (place, order, occurrence, group or value, length), and with `xmllint` validates the project's clean samples, the external ones (and fails the invalid ones), and every message a running mock writes. A fetch that fails on the network is tried three times with a growing pause; one with the wrong hash stops at once. Skips without a network or `xmllint`; `--require`, which CI passes, makes a skip a failure. |
| `tools/release.py` | Cuts a release in one step, run by the maintainer on a clean `main` after the release pull request has merged: it refuses, then tags, pushes and publishes the GitHub Release, which is what uploads to PyPI. Every refusal is something that has gone wrong in a real release - a dirty tree, a branch that is not `main` or a detached HEAD, a `main` that disagrees with `origin/main`, a `pyproject.toml` that does not say the version, no dated changelog section for it, fragments still waiting in `changelog.d/`, or the CI workflow not green on the commit about to be tagged - green decided by `ci_verdict`, a pure function over GitHub's answer, from the CI workflow's own runs only, since the scheduled release check attaches to the same commit and is correctly failing until the tag exists. The tag is asked of **origin** rather than of this clone, because after a failed push the two disagree and that is how a release gets tagged at the wrong commit; `gh release create --verify-tag` is the other half of that guard. The Release body is the version's own `CHANGELOG.md` section, extracted by `notes_for` and passed with `--notes-file`: on a squash-merged repository `--generate-notes` restates the commit titles, which the changelog says better and which somebody reviewed. Publishing is last because it is the only irreversible step. `--dry-run` prints each step and does none. On a version already tagged and published it says so and stops, which it asks before examining the tree, so an entry waiting for the next release is not read as a problem with an old one. Standard library, `git` and `gh`. |
| `tools/check_release.py` | Asks afterwards whether a release finished: the version `main` claims has a tag, and that tag has a published GitHub Release. Passes when there is no dated section for the version yet, which is the ordinary state between releases and the case that must not cry wolf. Fails naming what is missing when `main` carries a dated release with no tag, or a tag with no Release, or a draft one - a draft does not trigger the publish workflow, so PyPI keeps serving the previous version. Whether `gh` can resolve the repository at all is asked separately from whether the Release exists, so a checkout with no GitHub remote skips rather than reporting a false alarm; `--require`, which the workflow passes, makes that skip a failure. |
| `tools/check_changelog.py` | Fails if the changelog is malformed, if a released section changed, if `[Unreleased]` holds anything but the pointer at `changelog.d/`, if a fragment is named wrongly or empty, if a fragment vanished without a release being cut, or if a pull request touches `mockbank/` without adding a fragment (lifted by the `no changelog` label). `--assemble VERSION --date` writes the fragments into a release section, fixes the link references and deletes them, and does nothing the second time. |
